# Professional Report Artifact Generation

> **Goal**: Generate a polished, professional, UX-pleasant **HTML report artifact** (with a built-in "Save as PDF" path via print-optimized CSS) for the HFI / hedge-fund intelligence module, on-demand per user request. The artifact is generated by an LLM and rendered from **structured data** (not raw markdown), so layout is always clean and brand-consistent.
>
> **Status**: Approved plan (act-mode implementation pending).

---

## 1. Context — what already exists

The HFI subsystem already ingests hedge-fund content and has the building blocks for reports. The data pipeline is in place; the missing piece is a *deliverable artifact* rather than a markdown string in an accordion.

### Data layer (ready today)
- `Investor` — a hedge fund / institutional investor tracked for 13F monitoring.
- `HfiSource` — the origin of a piece of public content (13F filing, article, newsletter, video, …).
- `ContentItem` — a single ingested content item with `extracted_entities` (JSONB) and `extracted_theses` (JSONB).
- `PortfolioChange` — position deltas between 13F filing periods (new / increased / decreased / closed), with `shares_previous`, `shares_current`, `value_usd`, `percent_of_portfolio`, `filing_period`.
- `HfiReport` — already persists `content_markdown`, `title`, `summary`, period, `source_item_ids`, `is_read`.
- `HfiAlert` — high-priority events tied to a report.

### Existing report generation
- **Endpoint**: `POST /api/hfi/reports/generate/{investor_id}` (`src/api/hfi_reports.py`)
  - Aggregates the last 20 `ContentItem`s + latest 50 `PortfolioChange`s for the investor.
  - Calls the LLM with `INVESTOR_REPORT_PROMPT` → free-form markdown.
  - Persists a new `HfiReport` row.
- **Current LLM call site**: `src/pipeline/hfi/nodes/report_generator.py`
  - Uses **OpenAI** (`openai` SDK) with `model="gpt-5.4-nano"`, `temperature=0.3`, `max_completion_tokens=4000`.
  - `INVESTOR_REPORT_PROMPT` lives in `src/pipeline/hfi/prompts/report_generation.py`.
- **Frontend**: `web/src/app/(app)/investors/[id]/page.tsx`
  - "Generate Report" button (React Query mutation) + `Reports` tab listing reports as `ReportAccordionItem`s.
  - A selected report is rendered with `whitespace-pre-wrap` over `content_markdown` — functional but **not** a professional artifact.

### LLM access in the repo
- `src/config.py` exposes `anthropic_api_key` / `anthropic_model` (Claude) **and** `openai_api_key` / `openai_model` (default `gpt-4o`).
  - The **entire HFI pipeline** (entity extraction, thesis extraction, current report generation) uses **OpenAI**, and `OPENAI_API_KEY` / `OPENAI_MODEL` are in `.env` / `.env.example`.
  - The Anthropic settings are present but **not used** anywhere in the pipeline.
  - **Decision constraint**: no Claude/Anthropic model access is available. We therefore use **OpenAI** (already working) for report generation.

### Why OpenAI is fine (and preferable here)
- OpenAI supports **JSON mode** (`response_format={"type": "json_object"}`) and **strict JSON schemas**, guaranteeing the structured output we need and removing the need for JSON-repair fallbacks.

---

## 2. What "professional artifact" means here

- A **branded, full-page HTML report** viewable in-app, consistent with the app's existing design tokens.
- **Print-optimized** via `@media print` / Tailwind `print:` variants so the browser's "Save as PDF" produces a clean, paginated PDF **with zero new backend dependencies**.
- Sections rendered from structured fields (so tables are real tables, sentiment is styled badges, not ASCII art).

---

## 3. Design decisions

| Decision | Choice | Rationale |
|---|---|---|
| Artifact format | **HTML page** (viewable in-app) with **print-to-PDF** path | Zero new deps; best UX; matches the app's design system. |
| PDF generation | **Browser "Save as PDF"** (print CSS) | No WeasyPrint/Playwright system libs in Docker. User explicitly selected this. |
| LLM output | **Strict JSON** (structured) | Guarantees parseable structure; enables clean rendering. |
| LLM provider | **OpenAI** (`gpt-4o` for reports) | Already configured & working across the pipeline; Claude unavailable. |
| Schema change | Add nullable `content_json JSONB` to `hfi_reports` | Keeps `content_markdown` for backward compat (old reports / API consumers). |
| Generation mode | **Sync in-request** (cleaned up) | Simpler than Celery for on-demand "Generate Report"; fits existing loading UX. Flaggable to Celery later. |

## 4. Backend changes

### 4.1 New structured prompt
**File**: `src/pipeline/hfi/prompts/report_generation.py` (add alongside the existing markdown prompt).

Add `INVESTOR_REPORT_STRUCTURED_PROMPT` — the same narrative intent as the existing prompt, but instructing the model to return **strict JSON only**, conforming to:
```jsonc
{
  "title": "Intelligence Report: <Investor>",
  "executive_summary": "1-2 sentences of the most important developments",
  "key_observations": ["...", "..."],
  "companies": [
    {
      "ticker": "NVDA",
      "name": "NVIDIA Corporation",
      "sentiment": "bullish",          // bullish | bearish | neutral | mixed
      "conviction": "high",            // high | medium | low
      "context": "AI chip tailwinds ...",
      "quote": "short verbatim excerpt (<25 words)"
    }
  ],
  "bull_signals": [ { "ticker": "...", "thesis": "...", "catalysts": ["..."], "quote": "..." } ],
  "bear_signals":  [ { "ticker": "...", "thesis": "...", "risks": ["..."],   "quote": "..." } ],
  "conviction_indicators": { "strong_conviction": ["..."], "monitoring": ["..."] },
  "portfolio_changes": { "filing_period": "2024-06-30", "new_positions": [...], "increased": [...], "decreased": [...], "closed": [...] },
  "source_links": ["https://...", "..."]
}
```

### 4.2 Rewrite the generator
**File**: `src/pipeline/hfi/nodes/report_generator.py`

Add `generate_structured_report_from_context(...)` (keep the existing `generate_report_from_context` for any callers, or redirect it):

- Uses `OpenAI(api_key=settings.openai_api_key)`, model = `settings.openai_model` (default `gpt-4o`).
- `response_format={"type": "json_object"}`, `temperature=0.3` (or lower, e.g. `0.2`, for more consistent structure).
- Tenacity retry (`stop_after_attempt(3)`, `wait_exponential`) — same pattern as the current `_call_llm`.
- Parse + validate via a Pydantic schema (see 4.3); on validation failure, attempt once with a repair prompt; on repeated failure, persist the raw JSON and surface a clean error.
- Derive a simple `content_markdown` from the JSON (so old API consumers keep working).
- Persist the report (the executor already saves directly; **drop the `asyncio.sleep(0.5)` hack**).

Keep `report_generator_node(...)` (the pipeline node) working by having it call the new function with the same shape of args.

### 4.3 Pydantic schema
**File**: `src/schemas/hfi.py`

Add a `ReportStructuredContent` Pydantic model mirroring the JSON shape above (`sentiment`/`conviction` as Enums), used to validate model output before persistence.

### 4.4 DB migration
Add nullable `content_json JSONB` column to `hfi_reports`, with a migration in `alembic/versions/`. Keep `content_markdown` as the rendered fallback.

### 4.5 Endpoint cleanup
**File**: `src/api/hfi_reports.py`

- `POST /api/hfi/reports/generate/{investor_id}` — call the new structured generator; return the report directly (no sleep hack).
- Extend `ReportOut` schema with `content_json: dict | None` so the frontend can read the structured payload.

## 5. Frontend changes

### 5.1 Dedicated artifact page
**File**: `web/src/app/(app)/investors/[id]/reports/[reportId]/page.tsx`

A full-page, branded report view:
- **Cover header**: investor name, period, generation date, source/content counts.
- **Executive Summary** callout.
- **Key Observations** bulleted list.
- **Companies Discussed** table: Company | Ticker | Sentiment | Conviction | Context, with 🟢/🔴/🟡/🟠 sentiment badges and conviction chips.
- **Bullish Signals** / **Bearish Signals** cards (thesis + catalysts/risks + supporting quote).
- **Conviction Indicators** (strong / monitoring).
- **Portfolio Changes (13F)** table grouped by category (new / increased / decreased / closed) with shares/value/% columns.
- **Source Links** footer.
- Uses the app's existing design tokens (`ink`, `signal`, `canvas`, `panel`, `border-line`) and shadcn components (`Card`, `Badge`, `Table`).
- A `Download PDF` / `Print` button triggers `window.print()` (plus a `no-print` chrome toggle).

### 5.2 Print-optimized CSS
Add a dedicated stylesheet / `<style>` block for `@media print`:
- Hide app chrome (nav, header, floating action buttons, sticky tabs).
- Force section page breaks (`break-before: page` between major sections).
- Expand table borders; ensure color badges render legibly in B&W (use text labels, not color alone).
- Tailwind `print:` variants for any component-level hiding.

### 5.3 Wire-up
- "Generate Report" mutation → on success, **navigate to `/investors/{id}/reports/{reportId}`**.
- `Reports` tab list: each `ReportAccordionItem` gets an **"Open Report" link** to the artifact page.
- The existing accordion stays as a fallback for old markdown-only reports.

### 5.4 API client
**File**: `web/src/lib/api.ts`
- `getHfiReport(reportId)` already returns `ReportOut`; ensure `content_json` is included in the request typing (`HfiReport` interface). No new endpoint needed for fetching.

## 7. Out of scope / future options

- **Async / Celery queueing** of report generation (current plan uses cleaned-up sync in-request). Trivial later since the executor already detaches the save.
- **Server-side PDF** (WeasyPrint / Playwright) if true server-generated PDFs are ever required — not needed given the print-CSS path chosen.
- **Other LLM providers** (Gemini free tier, Groq): decoupled via prompt + Pydantic schema; swapping is a ~20-line change once keys are added to `settings`.
